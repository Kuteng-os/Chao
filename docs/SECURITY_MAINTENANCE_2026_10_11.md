## 本轮修复

| 问题 | 修复与验证 |
| --- | --- |
| 超限分块上传会继续等待请求结束 | 达到字节上限立即返回 413 并关闭未读连接；独立的 15 秒上传期限；验证未发送 EOF 时也能拒绝。 |
| 同时接收或处理的写请求无总量限制 | 请求接收及后续处理共用限额：全局 64 个、单身份 8 个、保留请求体上限合计 64 MiB；正常完成、中断、超时和失败均释放。 |
| 表情 PNG 的头部可被后续 IHDR 改写，交错 PNG 解压路径没有输出上限 | 完整校验容器，拒绝重复头、缺失结束块、尾随数据；按尺寸、位深和 Adam7 扫描线计算最大解压量，再解码。保留合法交错 PNG、透明像素及 GIF 处置行为。 |
| 卡面图片同步编解码占用 HTTP 主线程 | 卡面和表情共用最多两个图片工作线程，限制堆空间和处理时间，服务退出时停止处理。 |
| 房间/大厅串行队列无待处理数上限 | 大厅最多 32 个、单房间最多 64 个待处理请求；超限返回 429，维护巡检不再向忙碌房间追加任务或因此中止对局。 |
| 词条的参数范围与效果长度相乘，可能形成大量同步校验 | 增加展开遍历工作量上限；批量同步共享预算，不能拆成一批多个词条绕过。正常百点重甲参数仍可使用。 |
| 冻结词条目录接受无效的版本标识并触发 500 | 查询前校验 64 位小写哈希；无效输入返回 400，合法但不存在的版本返回 404，已存在的历史目录仍可正常查询。已用 `constructor` 查询复现旧错误，并通过 HTTP 回归验证修复。 |
| Ajv 8.17.1 依赖警报 | 升级至精确锁定的 8.20.0；npm audit 未报告已知依赖漏洞。原项目未开启漏洞涉及的 `$data`，没有发现本项目可触发该项 ReDoS 的入口。 |

依赖依据：[Ajv 官方修复说明](https://github.com/ajv-validator/ajv/releases/tag/v8.18.0)、[CVE-2025-69873 公告](https://github.com/advisories/GHSA-2g4f-4pwh-qvx6)。生产 Node 为 22.23.3，与 [官方发布记录](https://nodejs.org/en/blog/release/v22.23.3) 核对。

## 审计范围

检查了账号登录/密码重置/网页一次性登录、管理员与作者权限、卡牌/词条/阵营/卡包管理、报错和站内信的归属、图片/GIF/WAV 上传、请求解析、生成任务预算和取消、模型输出校验、联机指令与幂等、观战视角及隐藏信息、网页输出转义/CSP、静态资源路径、签名更新及服务进程权限。

补查了存储事务串行写入、共享牌组更新/撤回、删除关联内容与重复请求、每账号媒体配额及目录查询。除上述无效目录标识外，本次补查未确认新的权限绕过；线上报错仍为以下三条待明确或补全资料的记录。

生产服务以非 root 用户运行，已启用 NoNewPrivileges、ProtectSystem=strict、ProtectHome、PrivateTmp 和内存/进程数限制。没有对生产服务进行破坏性或压力测试；异常输入与并发验证在临时数据目录和未启用的新服务目录进行。此次审计覆盖上述应用入口，不等于证明系统不存在其他漏洞，也不替代外部网络层抗流量攻击设施。
