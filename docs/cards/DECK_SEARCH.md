# 指定卡牌检索与召唤

自客户端 0.8.5 / mechanics-7 起，卡牌和独立模板词条均可使用：

```json
{"trigger":"on_death","effects":[{"op":"summon_from_deck","card_name":"玉石","amount":1}]}
```

`search_deck` 将匹配卡加入手牌；`summon_from_deck` 将匹配的单位召唤到己方后援线。两者 `card_name` 为准确名称，1–32 字，无首尾空格或控制字符；`amount` 为 1–3。模板数量可用参数，例如 `{"param":"x"}`，整个参数范围必须落在 1–3。

名称属于卡牌命名空间，不是词条 ID。无需登记“玉石”词条、无需 `tokens`，也不要求目标卡已经存在于公共卡库。玩家应将目标卡实际编入牌组。AI 先正式复述，再经多轮修改和确认生成；不得将牌组召唤降级成抽牌或生成衍生单位。

## 结算

- 从己方牌顶向牌底查找第一个完全同名者，移出该张真实卡，不复制、不洗牌。检索召唤会跳过同名指令和反制；检索入手可获取任何类型。
- 同名不同作者或版本仍按当前牌序选择。保留对局冻结的定义、版本、作者归属、卡面和统计身份，不查询可变的公共卡库。名称修订不会回溯修改已登记效果中的 `card_name`。
- 找不到匹配不生效，不触发疲劳。召唤遇到后援线满员则停止，尚未召唤的卡留在牌组；数量不足只处理找到的卡。
- 检索入手遇到 10 张手牌上限，沿用抽牌溢出规则：该匹配卡烧毁。成功检索单独计入 `search` 统计，并纳入入手后的打出率；不记为普通抽牌。
- 从牌组召唤不支付部署费，不触发“对方部署单位”反制。无突击时当回合不能行动；突击和守护正常生效。真正的卡牌仍有回合、阵亡能力，离场进入弃牌区。
- 当前 DSL 把单位自身常驻规则编码为 `on_play` 中 `target=self,duration=battle` 的 `set_attack_limit / modify_operation_cost / set_combat_damage_multiplier / modify_stacks / set_stacks`。这些规则在牌组召唤时初始化一次，以保留奋战、重甲和常驻倍率等机制。其他 `on_play` 效果（抽牌、伤害、攻防增益、继续召唤等）不执行；限时层不初始化。不要用上述常驻编码表达“仅手牌部署时才增加”的条件行为。
- 阵亡单位先释放占位，再结算阵亡召唤。后续选目标使用同一事务重放，不能重复移动卡牌、生成单位或增加统计。
- 查找计入目标访问预算，常驻规则初始化计入操作预算。未知字段、随机/条件检索、从对方牌组召唤、指定作者或版本、浏览牌组手选均未支持，需澄清或报告缺失能力。

## 兼容与验证

旧卡定义及编译哈希保持不变。服务器检查直接效果及绑定词条；含新操作的牌组双方须为 build 805 或以上。局域网协议升为 `frontline-lan-4`，旧版本不可混局。

规则由 Node 与 Godot 使用同一 schema；覆盖直接效果、参数词条、冻结版本、满场/满手、无匹配、真实死亡、重放、私密视图和联网重试。网页可选择上述两种效果，填写准确卡名，卡库名称仅作为输入建议。
