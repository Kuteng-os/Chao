# 常见卡牌机制支持范围

当前能力修订：`mechanics-8`。这是本项目的实际实现清单，不是 KARDS 全规则，也不是任意规则都能执行的承诺。卡牌数值由玩家填写，DeepSeek 只把词条和附加机制转换成已实现的声明式效果。命名词条仍须独立预览、玩家确认和自动校验登记；示例不会自动加入共享目录。

## 已实现的机制

| 类别 | 当前支持 | 具体边界 |
| --- | --- | --- |
| 触发 | 登场、被召唤、己方回合开始、己方回合结束、阵亡、反制触发 | 指令仅登场；阵亡时不能以已离场自身为目标 |
| 目标 | 自身、登场/阵亡时指定单位、双方总部、友方/敌方全体单位、随机友方/敌方单位 | 登场用 play_target 或组内 target；延迟触发默认入场绑定 target，显式 timing=trigger 才在触发时选；不支持选择总部与单位的混合目标 |
| 抽牌 | 自己或对手抽 1–3 张 | 连续按张处理，满手烧牌、空库疲劳、致命后停止；可以与其他效果按顺序组合 |
| 伤害和回复 | 固定 1–10 点，或来源单位卡牌初始防御力引用 1–20；单体、随机、全体、总部 | 引用冻结版本，不受增减益影响；技能伤害不反击、不受守护阻挡；回复不复活、不超过当前生命上限 |
| 属性增减 | 攻击/最大生命各 -5…5 | 至少一项非零；累计伤害保留；有效攻击 0–30、最大生命 1–30 |
| 资源 | 恢复 1–3 点当前资源 | 不超过已有资源槽，不增加资源上限 |
| 召唤 | 召唤衍生单位 1–2 个；三种类型衍生卡可加入手牌 | 可带已登记词条和独立能力，完整语义见 [衍生卡合同](GENERATED_CARDS.md) |
| 突击和守护 | 固有引用或临时/永久授予 | 突击不返还行动；守护按战线约束普通攻击；模板不能动态授予词条 |
| 多次攻击（本批新增） | `set_attack_limit` 设置 1–4 次总上限 | 每次付费、反击；保留已用次数；不绕过部署限制、步兵推进锁定；反击不占主动次数 |
| 直接消灭（本批新增） | `destroy` 消灭场上单位 | 不比较生命、不造成伤害、不反击；触发阵亡；不能消灭总部；不等同放逐 |
| 行动费用（本批新增） | `modify_operation_cost` 增减 -4…4，不能为零 | 场上单位移动和攻击均受影响；所有层相加后截断至 0–4；不改部署费 |
| 战斗伤害倍率 | `set_combat_damage_multiplier`：1–4倍，按受伤方兵种和主动攻击/反击阶段过滤 | 最新匹配层覆盖，不相乘；不影响技能 damage；可针对总部；不绕过攻击合法性 |
| 持续与组合 | 本次在场期间 `battle`；当前全局回合结束 `end_of_turn`；有序效果 | 临时层独立到期，永久层保留；每牌展开后最多 4 能力、每能力 4 操作、合计 12 操作 |
| 参数词条 | 最多 4 个必填整数参数 | 全部允许取值必须合法，不能用公式、条件或字符串表达式；引用精确 ID 与版本 |
| 对战一致性 | 同一 Godot 引擎用于 AI、LAN、云服务器 | 云端重编译存档规则；权威结算、随机、费用、回合和次数，客户端仅提交行动 |

## 指令与反制

指令制作已提供明确类型入口；反制支持对方部署单位、打出指令、攻击总部三类。专用 on_reveal/trigger_unit/cancel_action 与精确结算、隐私、费用规则见 [补充合同](COUNTERS_AND_VERSIONS.md)。

## 本批操作的精确语义

“奋战，每回合可以攻击两次”是如下模板。`attacks` 表示总次数，不是增加两次；无需每回合再写一层永久效果。

```json
{"kind":"template","abilities":[{"trigger":"on_play","effects":[{"op":"set_attack_limit","target":"self","attacks":2,"duration":"battle"}]}]}
```

不同攻击上限层按应用顺序，最后仍有效的一层生效；到期恢复前一层，没有层时为 1。中途修改上限不重置 `attacks_used`：已经攻击一次后设置 2 次，只剩一次；设置为 1 则不能再攻击。只有目标控制者的新回合开始才归零。致命反击或胜负确定后不能继续攻击。费用为 0 仍受次数限制。步兵推进产生的本回合攻击锁定独立于次数，增大上限不会解除它。

```json
{"op":"destroy","target":"chosen"}
```

登场指定目标必须配套 `play_target`，与其他登场指定效果共享一个目标；阵亡指定目标使用能力组 `target`，见 [新增合同](DYNAMIC_DEATH_EFFECTS.md)。群体消灭先标记整批单位，再统一移除并按固定顺序捕获阵亡能力；当前能力剩余操作先结算，然后处理阵亡队列。后续回复不能救回已移除单位。消灭自身后，当前来源能力仍按快照执行。空目标无操作，已经支付的卡牌费用不退还。

```json
{"op":"modify_operation_cost","target":"all_friendly_units","cost_delta":-1,"duration":"end_of_turn"}
```

只影响此条效果结算时的单位，不影响以后进场者。场上行动费为 `clamp(基础行动费 + 所有未到期 cost_delta 之和, 0, 4)`；衍生单位基础行动费可设置0–4，旧模板默认1。先求和再截断，到期只移除自身来源层。卡面、悬停和拖动预览显示现值，原始卡牌定义和哈希不变。每次移动/攻击按执行前现值收费。

## 针对兵种的战斗伤害

“攻击步兵时伤害变为两倍”已支持，使用登场时赋予自身的持续规则，不需要通用 on_attack 或任意条件表达式：

```json
{"op":"set_combat_damage_multiplier","target":"self","against":"infantry","applies_to":"attack","multiplier":2,"duration":"battle"}
```

`against` 为 any/infantry/tank/artillery/fighter/bomber/hq；`applies_to` 为 attack/retaliation/both；`multiplier` 为整数1–4，可用词条参数。未指定反击时，“攻击…时”默认仅主动攻击。目标是获得此规则的场上单位，不能把总部当作增益接受者；against=hq 则表示该单位攻击总部的伤害倍率。

普通攻击与反击分别读取伤害来源自己的规则，按接受伤害者兵种过滤，最后仍有效且匹配的一层覆盖，不累计相乘。不改变主动攻击次数、费用、守护、射程或炮兵免反击等规则。技能 damage 数量不乘倍数。end_of_turn 到当前全局回合结束恢复之前的匹配层，battle 到单位离场结束。共享64层预算，超限回滚整个动作。

## 常见但尚未实现的机制与后续顺序

以下是实现路线，不是当前能力。模型遇到明确要求必须返回不支持/待实现；玩家确认也不能使未实现机制生效。

| --- | --- | --- |
| 2：事件与条件 | 攻击前后、受伤、造成伤害、击杀、友军部署/阵亡、对手回合、每回合首次触发 | 事件的 source/target、伤害类别、时点快照、触发频率、递归预算；“每次”不能偷偷变成登场 |

| 3：光环与沉默 | 持续光环、沉默、移除词条、追加攻击机会/刷新行动 | 新单位是否受光环；来源离场即时撤销；沉默移除范围；基础属性与伤害是否保留；刷新不等于总上限 |
| 4：牌区操作 | 弃牌、检索/发现、洗入、复制、生成手牌、回手、放逐、复活、变形、控制权转移 | 牌区身份、隐藏信息、费用/增益重置、满手/满场、随机可见性、重新登场触发、历史版本冻结 |
| 4：资源和回合 | 改部署费、改资源上限、下次行动免费、下一张牌费用、额外回合 | 一次性消耗时点、上限、持续期限、无效行动不消耗、先后手和断线恢复 |
| 5：交互 | 反应/反制、对手回合出牌、多阶段选择、多目标选择、延迟结算 | 优先权、计时、双方超时、合法目标变动、取消、恢复、动作幂等 |
| 无默认开放计划 | 任意 GDScript/脚本、执行网址、无限循环、无界变量/递归 | 不让模型或玩家提交任意可执行代码；新规则仍由受限操作与事件扩展 |

## 生成与澄清的覆盖规则

1. 已登记名称：引用准确版本，不把模板复制到卡牌内，不因同名假定同义。
2. 新命名词条：先独立提案；所有细节明确且可表达才预览，玩家确认后原子校验登记。
3. 缺触发、对象、次数、持续期或参数含义：只追问缺项，每轮最多三个。玩家明确的数值不改写；“增加两次”不能默认为“总共两次”。
4. 基础规则的默认行为无需反复确认：“抽一张”默认自己；“每回合攻击两次”沿用费用、部署和反击基线。玩家明确改这些规则时逐项验证是否支持。
5. 同时含支持与不支持的要求：完整指出缺口，不丢弃不支持部分，不拿大额伤害冒充消灭，不拿瞬时群体增强冒充光环。
6. 超出边界：明确范围，等待玩家修改；不要自动裁剪数值、偷换目标或拆操作绕过玩家意图与规则限制。
7. 取消、过期候选、重复确认、网络重试：沿用提案 revision/hash 和 request_id，过期确认拒绝；确认成功前不登记。失败保留输入。

## 扩展与验证入口

新增机制时必须同步 Card/Keyword Schema、Godot 合同、两端语义验证、编译、文本预览、权威解释器、模型提示、界面已有数值和测试。运行 `py -3.11 tools/sync_contracts.py` 更新 Godot 内嵌 Schema。

`GET /health` 的 `rules` 返回当前 `mechanics-8` 能力修订及从 Schema 推导的操作/触发白名单。模型也读取同源白名单。能力列表用于发现支持范围，不代替具体卡牌和参数校验，也不能替代客户端升级。

本次是保留旧操作语义和旧卡牌编译哈希的增量扩展：旧卡不重写；新效果须使用新版客户端。旧客户端不能解析新卡时会拒绝编译，不静默删效果。云端不接受客户端上传编译产物裁定对局。后续改变既有操作含义时必须升级规则/解释器版本，并保留历史对局对应实现，不能继续复用旧规则语义。

新增回归入口：`tests/test_mechanics.gd`、`tests/run_mechanics_parity.mjs` 以及 `server/test` 中登记与真实 Godot 权威对局用例。覆盖合法/非法输入、参数全范围、回合重置、过期层、零费、部署与推进、守护变化、反击死亡、层预算回滚及重复网络行动。未实现表格不作为已经通过的测试项目。
