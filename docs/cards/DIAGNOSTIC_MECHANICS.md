# 已收录机制修复协议

机制修订 mechanics-14：以下均已实现，不得再按旧版本提示拒绝。
一、事件：单位可以用 own_unit_deployed/enemy_unit_deployed 监听之后从手牌打出的其他单位，召唤不算、自身部署不算。own_order_played/enemy_order_played 在相应指令成功结算后触发；被反制取消不触发。on_attacked 在本单位受到主动交战前触发一次，trigger_unit 是攻击者；反击不是新的主动交战。on_damaged 在实际受伤后触发，免疫/全额重甲抵消的零伤害不触发；死亡单位不再结算其受伤能力。事件可选 limit=1..9，本次在场独立计数，各效果组分别计数，离场重置；首次写 limit:1。on_damaged 可选 damage_step=1..10，累计实际损失的防御力达到阈值时结算一次，余数保留；治疗不清除累计进度，重甲减免不算损失。每损失2防御获得1重甲：on_damaged,damage_step:2,effects:[{op:"modify_stacks",target:"self",stack:"heavy_armor",amount:1,duration:"battle"}]。持续光环和普通触发不得互相替代。
二、延迟指令：order 除 on_play 外，支持 next_own_turn_start、next_opponent_turn_start、next_own_order_played；打出指令后自动预留，不再扣费，仅下一次匹配事件结算一次。各延迟效果组的 premise 在该事件开始时同时锁定，再按组执行；不满足的组同样消耗，不继续等待。允许一张牌 on_play 即时效果和多个不同条件延迟组并存。三分支清场可分别比较 friendly_unit_count 与 enemy_unit_count 的 gt/lt/eq，分别 destroy 对应方和 damage 该方总部；相等要按玩家回答处理，不擅自省略任一方。下一回合指哪方不明确时询问。延迟指令不依赖来源单位存在。
三、transfer_card：{op:"transfer_card",source:"deck|discard|hand|self|starting_deck",destination:"hand|deck|support|source_position",mode:"move|copy",selection:"top|random|highest_cost",amount:1..3,filter:{...可选}}。source 为控制者的牌组、弃牌区、当前手牌、本卡、起始牌组去重卡池。hand/self/starting_deck 仅允许 copy；deck/discard 可 move 或 copy。最高费用从符合筛选的牌中随机取并列最高者。copy 不拿走原卡，move 消耗原卡；没有候选不生效。support/source_position 仅允许取单位，直接召唤不触发部署；source_position 为本单位触发前的位置，死亡时已记录战线和插入顺序，容量满或前线已被敌占领则不取出原卡。deck 去向为随机插入己方牌组，hand 满10张烧毁。冻结的实际卡牌保留版本，复制保留原始定义版本及已有永久属性层、永久附加能力，不复制临时在场属性、受伤、装备或行动记录；弃牌区包含死亡、打出的指令、弃牌，不包含放逐。复活使用 discard -> support,mode:move,filter.kind:unit。selection:top 为区域末尾优先（牌顶/最近弃牌）。
filter 可有 card_name、faction_id、kind、unit_class、min_cost、max_cost；均为交集。阵营必须使用 context.faction_catalog 中对应 id，不能编造，未登记请提问。事件能力还可使用 event_faction:true 与 event_cost_distance:0..12，按触发事件卡的阵营、部署费用筛选。示例下一张指令后从己方牌组随机将同阵营费用相差最多1的单位加入手牌：next_own_order_played + transfer_card source:deck,destination:hand,mode:move,selection:random,amount:1,filter:{kind:"unit",event_faction:true,event_cost_distance:1}。来源范围、加入区域、“费用相近”的差值不明确需询问；不能把当前手牌、己方起始牌组池冒充全部服务器卡库。全卡库随机生成尚不支持，必须明示，不偷偷换来源。
四、单位持续自增益：while_active 已支持单位，effects 仅 modify_stats,target:self,health_delta:0,duration:battle；attack_delta 可固定整数、单位计数或装备公式。可附加基于 enemy/friendly_unit_count/front_count/support_count 与 other_friendly_unit_count 的 premise，含 all/any/not。实时判定、条件失去立即撤回、不累计。前线仅 front_count；不能写“前线数包含后援线”。任意一方前线有单位使用 any 组合两个front_count>0，含自身位于前线。场地保留原有无条件群体攻防/重甲/行动费；持续光环禁止读取自身当前攻防形成反馈。
五、装备：equip/unequip={op,target:单位,tag:"剑",amount:1..3} 给单位附加/移除命名装备计数，同名0..10件，最多16类，无需创建新词条来充当装备计数。装备离场/抑制清除。modify_stats 的 attack_delta/health_delta 可写 {equipment:"剑",scale:2}，触发时读取一次；用于 while_active 自身攻击则实时读取。每装备一把剑攻击+2：while_active + modify_stats self attack_delta:{equipment:"剑",scale:2},health_delta:0,duration:battle。装备的取得由另外的卡牌 equip 效果完成，不凭空自带剑，不擅自添加装备。没有耐久/插槽/独立装备卡类别。
六、战斗修正：set_combat_damage_multiplier 增加可选 target_row:any/front/support、attack_delta:-10..10（只在本次匹配战斗的伤害基数中加减，不永久修改面板）；先 max(0,当前攻击力+attack_delta)，再乘 multiplier/divisor，取整、重甲。对前线单位攻击翻倍设 target_row:front,applies_to:attack,multiplier:2；攻击前线单位+10设 multiplier:1,attack_delta:10。未填 target_row 按 any。攻击力面板保持原值，若玩家要求永久增益要另行澄清。已有规则的最后匹配覆盖语义不变。
七、选择目标：play_target/ability.target 支持 side:ally/enemy/any，row:any/front/support，可选 include_hq:true。总部必须 row:any，chosen 只能配 damage/heal；无 include_hq 仍仅选单位。事件和延迟目标 target.timing 必须 trigger。普通阵亡/己方回合继续默认部署时绑定。玩家明确“任意单位包括总部”可据此表达，不得限定为仅敌单位。
参数必须有界，含伤害X可在词条 effect.amount 使用参数。damage_step/limit/filter/tag/equipment.scale 本次仅使用固定值，不允许任意表达式。能力组4、单组效果4、主体总效果12、整牌48以及执行预算继续有效。
正式复述只写玩家机制，不要夹入“引擎不支持”“需要新增”等实现分析。问题放 questions，真正缺失能力放 missing_capabilities，未明确取整/范围/时机仍需询问；不能以“通过”掩盖未回答的问题。复述不得增加玩家没说的限制，不得把前线扩大为全场。历史中的不支持结论不代表现在仍不支持，应依据本次规则与Schema重新判断。
